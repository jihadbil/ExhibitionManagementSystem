# خطة إصلاح المخاطر الحرجة في Backend وDesktop

**النطاق:** ASP.NET Core API، Services، DataAccess، Models، وتطبيق WPF فقط.  
**خارج النطاق الحالي:** واجهة Web، وأسرار/قيم بيئة الاختبار المخزنة محليًا.  
**الهدف:** إزالة الأعطال التي تمنع الوظائف، ومنع تجاوز الصلاحيات أو عبور بيانات المستأجرين، ثم إثبات ذلك باختبارات رجوع.

## حالة التنفيذ الحالية

- ✅ إصلاح عقد حذف الجناح وعقد بنود الفاتورة بين API وDesktop.
- ✅ إغلاق تجاوزات Tenant في فك الدمج وإزالة تخصيص المساحة، وحماية استعلامات المحذوفات العامة.
- ✅ جعل بنود الفاتورة وسجل Audit ذرّيين، وجعل بيانات الفاتورة المالية مشتقة من الخادم.
- ✅ إزالة Shadow FKs وإضافة ترحيلات القيود المالية وتخصيص المساحة الإعلانية الأحادي.
- ✅ Build Release بلا تحذيرات و87 اختباراً ناجحاً.
- ⏳ المتبقي قبل الإنتاج: تجربة الترحيلات على نسخة احتياطية من قاعدة فعلية، واختبارات SQL Server/API/Desktop الموسعة.

## بوابات الإنجاز

### G1 — إصلاح الوظائف المكسورة

- [x] إضافة Endpoint حذف الجناح الذي يستدعيه Desktop.
- [x] توحيد عقد بنود الفاتورة بين API وDesktop ومنع تمرير `invoiceId` خاطئ.
- [x] إضافة Contract tests للمسارات الحساسة التي تم إصلاحها.

### G2 — عزل المستأجرين والصلاحيات

- [x] تقييد فك دمج الأجنحة بـTenant المنفذ داخل الاستعلام نفسه.
- [x] تقييد إزالة تخصيص المساحة الإعلانية بالعقد والمساحة وTenant المنفذ.
- [x] حماية عمليات المستودع التي تتجاوز Query Filters بحيث لا تتجاوز Tenant filter ضمنياً.
- [x] منع ربط مساحة إعلانية بعقد معرض آخر أو تخصيص مساحة نشطة مرتين.
- [x] إضافة اختبارات Tenant A ضد Tenant B للعمليات السابقة.

### G3 — سلامة الماليات والتدقيق

- [x] منع القيم غير الموجبة لبنود الفاتورة والعقود والأسعار.
- [x] منع العميل من التحكم في رقم الفاتورة والإجماليات النهائية؛ الحساب يكون على الخادم.
- [x] جعل إضافة/تعديل/حذف بند الفاتورة وإعادة حساب الإجمالي عملية ذرية.
- [x] جعل حفظ بيانات المجال وسجل Audit ضمن Transaction واحدة.
- [x] إضافة قيود قاعدة بيانات للقيم المالية الحرجة.

### G4 — سلامة نموذج EF والترحيلات

- [x] إزالة العلاقات المكررة وShadow FKs (`ExhibitionID1`, `ExhibitorID1`, `InvoiceID1`, `VisitorID1`).
- [x] إضافة Migration تحذف الأعمدة الظلّية الفارغة والعلاقات الزائدة.
- [x] إضافة اختبار نموذج يمنع إعادة إنشاء Shadow FKs.
- [ ] اختبار Migration على قاعدة جديدة وعلى نسخة سابقة مع Rollback قبل النشر.

### G5 — الاختبارات والإطلاق

- [ ] اختبارات API فعلية عبر `WebApplicationFactory` لـ401/403/404/409.
- [ ] اختبارات SQL Server للتزامن في الحجز والدفع ومسح التذاكر.
- [ ] اختبارات ApiClients وViewModels الأساسية في Desktop.
- [x] فحص عدم وجود تغييرات EF غير مرحّلة، وتوليد migration script متكرر التشغيل بنجاح.

## ترتيب التنفيذ

1. إصلاح Tenant guards ومسارات Desktop/API المكسورة.
2. إضافة اختبارات رجوع لهذه الإصلاحات.
3. إصلاح ذرّية بنود الفاتورة وAudit.
4. تقوية Validation والقيود المالية.
5. إصلاح علاقات EF عبر Migration منفصلة بعد أخذ نسخة احتياطية.
6. إضافة اختبارات SQL/API/Desktop الموسعة.

## معيار الإغلاق

- Build Release بلا أخطاء أو تحذيرات.
- كل الاختبارات ناجحة.
- لا يمكن لـTenant A قراءة أو تعديل أو حذف سجل تابع لـTenant B.
- كل مسار يستدعيه Desktop موجود ومتوافق مع عقد الطلب والاستجابة.
- لا يمكن ترك بند فاتورة محفوظًا دون تحديث إجمالي الفاتورة المقابل.
- لا توجد Shadow FKs أو تحذيرات نموذج EF وقت التشغيل.
